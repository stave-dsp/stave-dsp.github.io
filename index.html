use stave::prelude::*;

#[derive(Params)]
pub struct GainParams {
    pub gain: FloatParam,
    pub bypass: BoolParam,
}

impl Default for GainParams {
    fn default() -> Self {
        GainParams {
            gain: FloatParam::new(ParamId(1), "Gain", Range::linear(-24.0, 24.0))
                .unit(Unit::Db)
                .smooth(Smooth::ms(10.0)),
            bypass: BoolParam::bypass(ParamId(2), "Bypass"),
        }
    }
}

pub struct Gain {
    params: Arc<GainParams>,
    gain: Smoother,
}

impl Plugin for Gain {
    const INFO: Info = Info { id: "com.example.gain", name: "Gain", vendor: "Example", ..Info::EFFECT };
    type Params = GainParams;

    fn new(params: &Arc<GainParams>, _telemetry: &Telemetry) -> Self {
        Gain { params: params.clone(), gain: Smoother::new(&params.gain) }
    }

    fn prepare(&mut self, env: &Environment) {
        self.gain.prepare(env);
    }

    fn process(&mut self, block: &mut Block<'_>) {
        let mut gain = self.gain.ramp(block, &self.params.gain);
        block.lanes::<2>().run(|frame| {
            let g = db_to_amp(gain.next());
            for lane in 0..frame.lanes() {
                frame.write(lane, frame.input(lane) * g);
            }
        });
    }
}

stave::export!(Gain);

Why Stave

Most plugin frameworks give you an API and leave verification to you. Stave makes verification part of the framework.

No black boxes

The VST3 and CLAP ABIs are written by hand in Rust. There's no JUCE, no wrapped C++ SDK and no clap-sys. When a host misbehaves you can read every line between it and your sample loop.

Struct layouts pinned against the official headers · Miri on the ABI tests

Realtime-safe, enforced

Every plugin's process loop runs under an allocation guard while its controls sweep, and its p99 block cost is checked against the realtime budget. Dropouts show up as failing tests, not bug reports.

process_never_allocates · deadline_headroom · Loom on lock-free protocols

Correct by measurement

The framework includes a measurement library covering THD, latency, transfer functions, aliasing and reverb tails. Tests assert what the plugin sounds like, not only that it ran.

stave-measure · per-project laws in tests/properties.rs

Observable while it runs

Lock-free taps, captures and breakpoints are built into every plugin and cost nothing when nothing is attached. Live CPU profiles and flamegraphs come from the host.

stave-telemetry taps · stave-play inspector

A DSP vocabulary, not a bag of filters

stave-dsp is organized by modeling method, and each layer builds only on the layers below it. Every stage shares one contract: prepare, reset, tick, plus reported latency and tail. Leaves and composites look the same to the code around them.

  1. kernel

    Composition forms: Serial, Par2, Loop, Router, Oversampled2x, PerChannel, VoiceRack. Each form's laws are pinned by tests.

  2. primitives

    Filters, delay lines, envelopes, LFOs, oscillators, resampling and deterministic randomness.

  3. behavioral

    Saturation curves with antiderivative antialiasing (ADAA), slew, hysteresis and nonlinear RC.

  4. circuit

    Device models, solvers and topologies derived from real schematics.

  5. structures

    Addressable chains (Chain) and a modulation matrix.

Every primitive has a measured price: tests/datasheet.rs prints its cost in ns/sample.

Tools for humans and agents

Stave includes its own host. It loads any VST3, stave-built or third-party, and gives you the same measurements from a window, a CLI or Rust.

stave-play

Play the plugin through its own face with a built-in keyboard and sine bank. Watch scope, spectrum and measured response, and profile CPU down to a flamegraph.

stave-bench

A headless measurement CLI. --describe lists the plugin's identity, every parameter and every preset as JSON, so a coding agent can drive, render and validate a plugin without ever opening a DAW.

stave-storybook

Every UI component is live and interactive without loading a plugin. Design-system work happens in isolation and can be captured in one command.

Validated on every commit

Each plugin mounts the shared suite in one line, stave_test::plugin_checks!, and new plugins start out passing it. CI also runs the Steinberg validator and clap-validator.

reproducible

Two instances given the same input produce bit-identical output

param_sweep

Every control swept to its extremes without NaN or runaway peaks

state_roundtrip

Saving, loading and saving again produces identical bytes

bypass_honest

Bypassed output equals the delayed dry input, bit for bit

process_never_allocates

The process loop never touches the allocator

deadline_headroom

p99 block cost stays within the realtime budget

The first build of Tilt, Stave's worked example, had its one knob backwards, and it passed every generic check. A measurement caught it. That's why every Stave project also states its own laws.

Get started

One command creates a complete project that already passes every gate: its params, the plugin, a styled face and the full test suite.

$ git clone https://github.com/stave-dsp/stave
$ git clone https://github.com/stave-dsp/stave-plugins && cd stave-plugins
$ bash scripts/new-plugin.sh myplugin
$ bash scripts/install.sh stave-myplugin-vst3 release
$ cargo run --release --manifest-path ../stave/Cargo.toml -p stave-play -- "$PWD/build/StaveMyplugin.vst3"
